## 交付行为

- 快速模式逐步显示模型正文；深度模式先显示规划、资料收集等真实阶段，再流式显示正文，触发质量修订时替换临时回答。
- 生成中可停止，保留已收到的文字并标记状态。取消已关联的上游模型请求；已经进入的外部工具调用可能继续完成，其结果不再追加到已停止的回答。
- 开始生成即保存会话轮次，终止时保存完整或部分回答。断流后刷新历史，仍在生成的轮次定期读取服务端状态；超时轮次显示为中断。仅完整轮次进入后续默认上下文。
- 请求 ID 隔离事件，终态之后不接受迟到正文或结果。服务端按快速／深度模式记录首字延迟与总耗时。

## 接口与数据兼容

- 新增 `POST /api/ai/chat/streams/{id}`，请求 ID 为 UUID，正文沿用问答请求并要求 `conversationId`；JWT 鉴权与限流仍生效。响应为 SSE，包含 `stage`、`delta`、`reset` 和 `terminal` 事件。
- 新增 `DELETE /api/ai/chat/streams/{id}`，仅允许停止当前账号的活动请求。保留原同步 `/api/ai/chat` 接口。
- `reading_ai_turn` 新增可空的唯一 `requestId` 和 `streamDeadline`；历史响应新增 `requestId`，轮次状态包含 `generating`、`stopped`、`interrupted`、`failed`。旧记录仍可读取。
- 当前配置使用 JPA `ddl-auto: update` 更新表结构；使用独立数据库迁移流程的环境需先添加这两个字段和请求 ID 唯一约束。
